# DCRYPT-2026-0004: streaming AEAD does not authenticate stream structure

> Published as [GHSA-8cwp-4826-jg9f](https://github.com/ioi-foundation/dcrypt/security/advisories/GHSA-8cwp-4826-jg9f).
> `DCRYPT-2026-0004` is a repository-local identifier, not an assigned RustSec
> ID.

> [!WARNING]
> `2.0.0` remediates this specific issue, but the release is withdrawn for a
> separate implementation-policy violation and is not a supported upgrade
> target. `3.0.0` is the supported replacement. `1.2.3` is not a safe fallback;
> see the [withdrawal notice](V2.0.0-WITHDRAWAL.md).

| Field | Value |
| --- | --- |
| Package | `dcrypt-symmetric` |
| Affected | All published versions before `2.0.0` (`>=0.9.0-beta.1, <2.0.0`) |
| Remediated | `2.0.0` (withdrawn); supported replacement `3.0.0` |
| Severity | High |
| Categories | Truncation, omission, replay, reordering, denial of service |

Version-1 GCM and ChaCha20-Poly1305 streams used unauthenticated terminator,
counter, and length fields. Decryptors trusted transmitted counters, allocated
from unbounded lengths, and discarded plaintext that did not fit a caller's
single read buffer. An attacker could obtain successful truncated EOF, omit,
replay, or reorder frames, or request an allocation approaching 4 GiB.

The `2.0.0` `DCRSTRM2` format authenticates its version, algorithm, random
stream identifier, base nonce, strict sequence, bounded lengths, final flag, and
caller AAD. It enforces the next sequence, requires authenticated finality and
physical EOF, bounds frames to 16 KiB before allocation, retains partial-read
plaintext, and rejects legacy version-1 input.

Existing version-1 ciphertext cannot retrospectively prove completeness or
ordering and must be migrated through an application-specific, explicitly
trusted legacy process. Do not deploy the withdrawn `2.0.0` release; upgrade to
`3.0.0` or later.
