# DCRYPT-2026-0001: safe error-registry APIs can cause undefined behavior

> Published as [GHSA-7hc7-h3f2-r4j6](https://github.com/ioi-foundation/dcrypt/security/advisories/GHSA-7hc7-h3f2-r4j6).
> `DCRYPT-2026-0001` is a repository-local identifier, not an assigned RustSec
> ID.

> [!WARNING]
> `2.0.0` remediates this specific issue, but the release is withdrawn for a
> separate implementation-policy violation and is not a supported upgrade
> target. `1.2.3` is not a safe fallback. No supported patched release is
> currently available; see the [withdrawal notice](V2.0.0-WITHDRAWAL.md).

| Field | Value |
| --- | --- |
| Package | `dcrypt-api` and crates re-exporting its error API |
| Affected | All published versions before `2.0.0` (`>=0.9.0-beta.1, <2.0.0`) |
| Remediated | `2.0.0` (withdrawn; no supported patched release) |
| Severity | Critical |
| Categories | Memory corruption, type confusion, use-after-free |

The affected `ErrorRegistry` erased `Box<E>` allocations to raw pointers,
deallocated them using the layout of `Box<()>`, allowed unchecked generic
retrieval as an unrelated type, and returned data without retaining ownership
against concurrent replacement. Ordinary safe Rust could therefore trigger
undefined behavior.

The `2.0.0` remediation stores owned `Box<dyn Any + Send>` values behind a
mutex, performs checked downcasts, clones outside the registry lock, and uses a
mutation generation so concurrent stores/clears win safely. The global slot is
retained only for compatibility; callers should return errors normally.

Stop using the affected registry API where feasible and await a supported
replacement release.
