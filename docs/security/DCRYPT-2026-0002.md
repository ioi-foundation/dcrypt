# DCRYPT-2026-0002: Ed25519 identity public key permits universal forgery

> Published as [GHSA-7j32-2mpw-c784](https://github.com/ioi-foundation/dcrypt/security/advisories/GHSA-7j32-2mpw-c784).
> `DCRYPT-2026-0002` is a repository-local identifier, not an assigned RustSec
> ID.

> [!WARNING]
> `2.0.0` remediates this specific issue, but the release is withdrawn for a
> separate implementation-policy violation and is not a supported upgrade
> target. `1.2.3` is not a safe fallback. No supported patched release is
> currently available; see the [withdrawal notice](V2.0.0-WITHDRAWAL.md).

| Field | Value |
| --- | --- |
| Package | `dcrypt-sign` |
| Affected | All published versions before `2.0.0` (`>=0.9.0-beta.1, <2.0.0`) |
| Remediated | `2.0.0` (withdrawn; no supported patched release) |
| Severity | Critical |
| Category | Authentication bypass |

The affected Ed25519 parser accepted the Edwards identity as a public key. A
signature with `R = B` and `S = 1` then verified for every message because the
challenge term multiplied the identity. The implementation also admitted other
noncanonical/small-order inputs and performed secret-dependent scalar
multiplication.

The `2.0.0` remediation replaces the custom arithmetic with
`ed25519-dalek`, uses strict verification, and rejects noncanonical,
small-order, and non-torsion-free public keys and `R` values as well as
noncanonical `S >= L`.

Consumers that accepted externally supplied dcrypt Ed25519 keys should audit
trust stores and historical authorizations. Updating software does not invalidate
actions previously authorized through a forged signature. Stop relying on the
affected verifier where feasible and await a supported replacement release.
