# DCRYPT-2026-0007: BLS12-381 hash-to-curve is incompatible with RFC 9380

> Drafted as [GHSA-g6wj-4vqj-4923](https://github.com/ioi-foundation/dcrypt/security/advisories/GHSA-g6wj-4vqj-4923).
> `DCRYPT-2026-0007` remains the repository-local tracking identifier; a CVE
> has been requested but not yet assigned.

| Field | Value |
| --- | --- |
| Package | `dcrypt-algorithms` |
| Affected | Every published version from `1.2.0` through `2.0.0` |
| Patched | `3.0.0` |
| Severity | Moderate |
| CWE | CWE-327: Use of a Broken or Risky Cryptographic Algorithm |

## Impact

The affected G1 random-oracle path expanded only one field element and mapped
directly to the target curve without the required simplified SWU map and
11-isogeny. The G2 path used an incorrect octet-to-field interpretation and an
incompatible square-root/fallback construction. Both paths disagree with every
tested RFC 9380 vector and independent implementation output.

Signatures or proofs derived from these functions are not interoperable with
standard BLS12-381 hash-to-curve implementations. The construction also lacks
the random-oracle and distribution arguments attached to the RFC 9380 suite.
No concrete signature forgery attributable solely to this hash-to-curve defect
has been established; the demonstrated impact is standards failure and loss of
the standard construction's assurance.

## Remediation

Version `3.0.0` implements the RFC 9380 BLS12-381 G1 and G2 suites with XMD
SHA-256, hash-to-field, simplified SWU maps, the required 11- and 3-isogenies,
cofactor clearing, and oversize-DST handling. Official vectors and an excluded
independent oracle cover both groups, multiple messages, encodings, scalar
hash-to-field, and oversize domain separation tags.

The high-level BLS APIs use fixed ciphersuite domain separation tags; arbitrary
runtime tags are not accepted by the standard facade.

## Workarounds

Do not generate or verify standard BLS signatures with the affected dcrypt
hash-to-curve output. Existing nonstandard objects must not be relabeled as
RFC 9380 or standard BLS objects. Migrate through an application-specific
process that can authenticate provenance and regenerate standard objects.
