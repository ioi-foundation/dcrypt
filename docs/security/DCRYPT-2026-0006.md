# DCRYPT-2026-0006: BLS12-381 G1 decoders bypass subgroup validation

> Published as [GHSA-rcw6-8w42-2cg2](https://github.com/ioi-foundation/dcrypt/security/advisories/GHSA-rcw6-8w42-2cg2).
> `DCRYPT-2026-0006` remains the repository-local tracking identifier; consult
> the GHSA for the current CVE assignment status.

| Field | Value |
| --- | --- |
| Package | `dcrypt-algorithms` |
| Affected | Every published version from `0.13.0-beta.1` through `2.0.0` |
| Patched | `3.0.0` |
| Severity | High |
| CWE | CWE-1287: Improper Validation of Specified Type of Input |

## Impact

The affected `G1Projective::from_bytes` and nominally validated G1 decoder
routed compressed input through the unchecked affine parser. The G1 surface
therefore accepted canonical, on-curve points outside the prime-order subgroup.
A concrete nonzero G1 torsion point was accepted by every published artifact in
the affected range. The G2 compressed decoder performed its subgroup check and
is not included in this root-cause claim.

Subgroup validation is mandatory for BLS public keys and signatures. Accepting
points outside the required group invalidates the assumptions used by standard
BLS verification and aggregation; the precise exploitability of a nonzero
torsion point depends on the caller's protocol.

## Remediation

Version `3.0.0` makes the generic G1 compressed decoder enforce canonical
encoding, curve membership, and subgroup membership. It provides separate
high-level BLS public-key and signature types: public keys reject identity as
required by `KeyValidate`, while signature decoding follows the ciphersuite's
distinct canonical/subgroup contract. Standard verification is exposed through
complete scheme APIs rather than requiring callers to compose core primitives.

Regression tests preserve non-subgroup encodings, identity behavior, valid and
invalid pairing equations, and independent cross-implementation encodings.

## Workarounds

Do not use the affected dcrypt BLS point decoders for externally supplied keys
or signatures. An independently reviewed implementation that performs
canonical decoding, subgroup checks, public-key nonidentity validation, and a
complete standard BLS scheme is required.
