# DCRYPT-2026-0009: zero-nonce XChaCha operations reuse a one-time nonce

> `DCRYPT-2026-0009` is a repository-local identifier. A GHSA, CVE, or
> RustSec identifier has not yet been assigned.

| Field | Value |
| --- | --- |
| Package | `dcrypt-algorithms` |
| Affected | Every published version from `0.9.0-beta.1` through `1.2.3` |
| Removed | `2.0.0` (withdrawn); supported replacement `3.0.0` |
| Severity | High |
| CWE | CWE-323: Reusing a Nonce, Key Pair in Encryption |

## Impact

The affected `XChaCha20Poly1305` surface exposed convenience operations that
always encrypted or decrypted with an all-zero nonce. Reusing either operation
under one key necessarily reused the ChaCha20 keystream and the Poly1305
one-time authentication key.

For equal-length messages, an observer can compute the XOR of the plaintexts.
If one plaintext is known, the other can be recovered with
`ciphertext1 XOR ciphertext2 XOR plaintext1`. Repeating a plaintext under one
key also produces identical ciphertext and tag. Reusing the Poly1305 key
invalidates the construction's authenticity assumptions and can enable tag
forgery analysis.

The repository reproduces the plaintext-recovery condition against the exact
`dcrypt-algorithms 1.2.3` artifact. Applications that invoked the zero-nonce
helpers more than once under a key must treat confidentiality and authenticity
under that key as compromised.

## Remediation

Version `2.0.0` removed the zero-nonce helpers, but that release is withdrawn
and yanked for separate implementation-policy failures. Version `3.0.0` is the
first supported replacement: it exposes a dcrypt-owned implementation of the
standard XChaCha20-Poly1305 construction, requires an explicit 24-byte nonce for
every operation, and never obtains randomness internally.

The former dcrypt construction was also not standard XChaCha20-Poly1305, a
distinct standards defect tracked as
[DCRYPT-2026-0010](DCRYPT-2026-0010.md). Its ciphertext is rejected by the
standard API rather than being silently reinterpreted.

## Workarounds

Stop using the affected zero-nonce operations immediately. Do not attempt to
repair prior ciphertext by assigning it a fresh nonce after the fact. Rotate
affected keys, review encrypted data and accepted tags, and re-encrypt trusted
plaintext with unique nonces under the supported construction.

Legacy ciphertext can be decrypted only after authenticating its provenance,
using the isolated, non-published
[decrypt-only migration tool](../../migration/legacy-xchacha20poly1305/README.md).
The migration tool does not make affected ciphertext cryptographically safe.
